# Datasets

The [catalog](datasets.tsv) lists the 94 benchmark tasks, dimensions, source and raw curator. `tabbiomed/configs/datasets.json` defines their ordered scope and portable feature, target, metadata and split identities. Dataset licenses and original source terms remain attached to each task.

The pinned Hugging Face release is the authoritative input for benchmark evaluations. The loader verifies local copies against that release before evaluation. Download the released data with:

```bash
python -m tabbiomed.data download --data-root data/processed
python -m tabbiomed.data verify --data-root data/processed
```

The downloader uses the pinned `TabBioMed/TabBioMed` Hugging Face revision in `tabbiomed/configs/data_source.json`. It reconstructs arrays from Parquet, preserves feature and row order, restores outer splits and sample groups, and checks scientific identities before installing a task. An existing dataset is checked rather than overwritten. `TBM_PARQUET` may point to a local copy of the same Parquet release.

## Reference curation

Code under `tabbiomed/data/curation/` documents the raw-source processing and can be run independently for the benchmark tasks. It is separate from the official benchmark data-loading workflow. Regenerated arrays are not required to run the benchmark and may differ slightly across numerical environments.

To run a reference curator, use a workspace containing the raw files under `data/raw/`. The source-specific options are available through `--help`:

```bash
python -m tabbiomed.data curate openml -- --help
python -m tabbiomed.data curate openml -- --input data/raw/OpenML_datasets --output data/unified_format
```

`python -m tabbiomed.data curate --workspace PATH SOURCE` runs from another workspace. The optional `data prepare` command normalizes target labels, retains source-defined partitions, constructs the specified outer CV when required, removes constant or empty features using the original selection partition, and installs a reconstruction only if its complete identity matches the release. Genomic tasks retain their pinned source column indices, including the original sexcheck constant-feature mask. Inputs that produce a different cohort, feature order or partition are rejected. It never overwrites an existing processed task.

Install only the curation extras needed for a source, for example `uv pip install -e '.[curation-molecules]'`. Original raw datasets are downloaded separately. The six genomic annotation tables are included in `tabbiomed/configs/curation/genomic_annotations/` and used automatically by both curation and PLINK subset preparation. Users do not need to supply annotation tables. The original genotype files remain separate raw source inputs.

The genomic subset preparation command is `python -m tabbiomed.data.curation.plink_subsets RAW_ROOT`, requiring PLINK2. SNP thinning uses seed 42 and preserves the original positional selection for the consecutive chromosome 22 task. Raw input releases and tool versions must reproduce the published subset identities.

ESM embeddings use `protenc==0.1.6` with mean-pooled residue representations from `esm2_t12_35M_UR50D`. Regenerated embeddings can differ slightly at floating-point precision across devices. Dataset identity checks require the exact released values, which the pinned Parquet release provides.

## Adding datasets

For a proposed dataset, include curation code and document:

- The original source, release version or persistent identifier, and how to obtain the raw inputs.
- What each row represents, the target meaning and label mapping, and when predictors are available where timing matters.
- Feature construction and preprocessing, including which transformations are fitted on training data.
- Excluded variables and the reasons for exclusion, plus how duplicates and conflicting labels are handled.
- The split rationale and protocol, including any patient, batch, scaffold or sequence groups kept together.

Use the existing [reference curators](../tabbiomed/data/curation/) as examples. For datasets registered in the release catalog, check local arrays and partitions against their pinned identities with:

```bash
python -m tabbiomed.data verify DATASET_NAME --data-root data/processed
```

This command verifies agreement with the registered release. Source interpretation and the suitability of features and splits also require review.
